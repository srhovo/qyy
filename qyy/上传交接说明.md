## 二、完整性校验（上传后必须核对）

**BASE64 编码内容**存放在同级的 `上传载荷/` 目录，每个文件一个 `.b64`：

```
上传载荷/index.html.b64                       ← 对应 index.html
上传载荷/nojekyll.b64                         ← 对应 .nojekyll（空文件）
上传载荷/assets/audio/tebie_intro.mp3.b64
上传载荷/assets/img/me_400.webp.b64
上传载荷/assets/img/me_400.jpg.b64
上传载荷/assets/img/her_400.webp.b64
上传载荷/assets/img/her_400.png.b64
```

执行 Agent 应当用这些 base64 **直接**作为 `content` 传给 GitHub blobs API，
**不要**从别处找文件、不要重新编码。

> **注意路径映射**：`nojekyll.b64` 解码后要写成仓库里的 **`.nojekyll`**（带前导点），
> 这是文件名里唯一一个需要改名的。其余 `.b64` 去掉扩展名即可。

或者，如果执行环境能直接访问本机 `/workspace/github-pages-ready/`，
也可以直接从那里读原始文件再 base64 编码 —— 两条路径产出的内容 sha256 完全一致。

## 三、推荐的上传方式：GitHub Git Data API

这套 API 能在**一次调用里提交多个文件**，不比逐个 PUT Contents 慢。

### 步骤

**1. 建仓库（若无）**

```
POST /user/repos
{ "name": "<仓库名>", "private": false, "auto_init": false }
```

> Pages 免费版**只支持 public 仓库**。

**2. 取 HEAD（空仓库时此步会 409/404，属正常，跳过）**

```
GET /repos/{owner}/{repo}/git/ref/heads/main
```

**3. 为每个文件创建 blob**

```
POST /repos/{owner}/{repo}/git/blobs
{ "content": "<文件的 base64>", "encoding": "base64" }
→ 返回 { "sha": "..." }   ← 应等于上面「git blob hash」表里的值
```

**4. 创建 tree**

有父提交时带 `base_tree`：
```
POST /repos/{owner}/{repo}/git/trees
{
  "base_tree": "<父 commit 的 tree sha，空仓库则省略>",
  "tree": [
    { "path": "index.html", "mode": "100644", "type": "blob", "sha": "<blob1>" },
    { "path": ".nojekyll", "mode": "100644", "type": "blob", "sha": "<blob2>" },
    { "path": "assets/audio/tebie_intro.mp3", "mode": "100644", "type": "blob", "sha": "<blob3>" },
    { "path": "assets/img/me_400.webp", "mode": "100644", "type": "blob", "sha": "<blob4>" },
    { "path": "assets/img/me_400.jpg", "mode": "100644", "type": "blob", "sha": "<blob5>" },
    { "path": "assets/img/her_400.webp", "mode": "100644", "type": "blob", "sha": "<blob6>" },
    { "path": "assets/img/her_400.png", "mode": "100644", "type": "blob", "sha": "<blob7>" }
  ]
}
```

> `assets/` 目录条目**不需要**显式创建 —— Git 会从文件路径自动推导。写成
> `assets/audio/xxx` 这种带斜杠的路径即可。

**5. 创建 commit**

```
POST /repos/{owner}/{repo}/git/commits
{ "message": "birthday page", "tree": "<tree sha>", "parents": [<父 commit sha，空仓库则 []>] }
```

**6. 更新 ref**

```
POST /repos/{owner}/{repo}/git/refs
{ "ref": "refs/heads/main", "sha": "<commit sha>" }

# 若 main 已存在：
PATCH /repos/{owner}/{repo}/git/refs/heads/main
{ "sha": "<commit sha>", "force": false }
```

**7. 开启 Pages**

```
POST /repos/{owner}/{repo}/pages
{ "source": { "branch": "main", "path": "/" } }
```

**8. 验证 Pages 生效**

```
GET /repos/{owner}/{repo}/pages
→ 看 status 是否为 "built"，取 html_url
```

首次构建要等 1~2 分钟。若返回 `status: "building"`，等 30 秒重试（**不要**高频轮询）。

## 四、上传后验收（必做）

拿到 Pages 链接后，逐个核对返回 **200**：

```
GET https://{owner}.github.io/{repo}/
GET https://{owner}.github.io/{repo}/index.html
GET https://{owner}.github.io/{repo}/assets/audio/tebie_intro.mp3
GET https://{owner}.github.io/{repo}/assets/img/me_400.webp
GET https://{owner}.github.io/{repo}/assets/img/me_400.jpg
GET https://{owner}.github.io/{repo}/assets/img/her_400.webp
GET https://{owner}.github.io/{repo}/assets/img/her_400.png
```

**内容抽查**（防止 CDN 缓存了旧版本）：
- `index.html` 里搜 `ageGlow` —— 有则版本正确（这是最新版才有的蛋糕幕"19"元素）
- `index.html` 里搜 `callTimer` —— 有则版本正确（最新版才有的来电计时器）
- `index.html` 里搜 `poem` —— 有则版本正确（最新版才有的开场诗）

> 若这三个关键词任一缺失，说明 CDN 还在吐旧版本或上传失败，**等待 1 分钟重试**，
> 别急着改文件。

## 五、注意事项

1. **`.nojekyll` 不能漏**。它能让 GitHub 跳过 Jekyll 处理。虽然本项目全是静态文件、
   没有下划线开头的目录，Jekyll 本来也不会捣乱，但少一层保险总归不踏实。

2. **文件名含中文**（`使用说明.md`、`GitHub-Pages部署说明.md`）在 API 里要用
   UTF-8 编码的路径，GitHub API 支持，但保险起见，**这两个 .md 可以最后传，
   传失败也不影响页面运行**。

3. **音频 1.2MB，PNG 208KB** —— 都在 GitHub 单文件 100MB 限制内，无需 Git LFS。

4. **不要改动 `index.html` 的内容**。它是自包含单文件，所有 CSS/JS 内联，
   没有任何外部 CDN 依赖。改一个字符都会破坏 blob hash 校验。

5. **私有仓库无 Pages**（免费账号）。若用户坚持要私有，只能降级为"打包发给对方本地打开"。
